# Entrega B-63 · Escalón 4 sobre el motor CDX de Wayback

## 1. Resumen Ejecutivo y Motivación

- **Problema resuelto (P-4):** En la Fase 4, el Escalón 4 de la escalera de recuperación contenía lógica cableada exclusivamente para dos datasets (`bcb/deuda_externa` e `ine/rendicion_cuentas`), llamando a la Availability API con un timeout reducido de 2 s y sin utilizar el motor CDX ni el sistema de caché en disco (`external_cache`).
- **Qué se construyó:**
  1. Se agregó la función `query_cdx_snapshots` en `src/crawler/core/wayback_engine.py`, configurada con timeout de al menos 15 s, reintentos con backoff exponencial, soporte para sesión inyectada, normalización de esquemas y caché persistente en disco vía `external_cache`.
  2. En `src/crawler/core/recovery_ladder.py`, se eliminaron todos los condicionales cableados por portal/dataset en `_try_rung_4_wayback_archive`.
  3. Se diseñó el método de inferencia dinámica `_get_dataset_cdx_pattern` que determina automáticamente el patrón de búsqueda comodín (`/*`) para la API CDX a partir de las URLs documentales observadas del dataset en `inventory.db` o semillas de configuración.
  4. Se implementó `_snapshot_matches_period` para asociar instantáneas históricas a períodos faltantes en periodicidades anual, semestral, trimestral y mensual.
  5. Se marca explícitamente el recurso recuperado como procedente del archivo histórico (`is_historical_archive=True`, `archive_source="wayback_machine"`).
  6. Se actualizó el modo `--dry-run` de `scripts/recuperar_periodos.py` para consultar el motor CDX y presentar las consultas y el total de instantáneas descubiertas para los 6 datasets con huecos detectados.
