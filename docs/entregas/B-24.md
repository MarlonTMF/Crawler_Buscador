En este bloque se abordaron dos objetivos complementarios esenciales para la robustez y cobertura profunda del prospector:

### A. Precondición O-31 / E-17: Deduplicador Intra-Corrida Estricto
- **En `DiscoveryEngine` (`src/crawler/core/discovery.py`):**
  - Se implementó el conjunto `enqueued_urls` para evitar que una misma URL de navegación sea encolada múltiples veces en la cola BFS cuando distintas páginas de un mismo nivel enlazan a ella.
  - Se implementó `seen_candidate_urls` para evitar que el mismo recurso descargable sea agregado varias veces a la lista de candidatos con distintos textos de anclaje.
- **En `CrawlOrchestrator` (`src/crawler/core/orchestrator.py`):**
  - Se incorporó `seen_canonical_urls` en el bucle principal de extracción, garantizando que un recurso canónico no comprimido se procese y audite una sola vez por corrida.
- **Resultado empírico verificado:** En la base SQLite `output/bcb/inventory.db`, la corrida calibrada arrojó exactamente `COUNT(*) == 118` y `COUNT(DISTINCT download_url) == 118` (**0 duplicados intra-corrida**).
