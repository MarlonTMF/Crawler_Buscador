## 2. Implementación Técnica

### A. Detección Multi-Heurística de Paginadores (`_extract_pagination_links`)
El método inspecciona el DOM HTML buscando enlaces de avance paginado mediante 5 capas de detección:
1. **Atributo estándar `rel="next"`**: `<link rel="next" href="...">` y `<a rel="next" href="...">`.
2. **Patrones en parámetros de consulta (Query Params)**: Expresión regular `[?&](page|p|pagina|paged|offset|start)=(\d+)`. Ejemplo: `?q=reporte-estadistico&page=2` en Drupal del BCB.
3. **Patrones en ruta (Path Segments)**: Expresión regular `/(?:page|p|pagina)/(\d+)/?`. Ejemplo: `/category/boletin_financiero/page/2/` en WordPress de ASOFIN.
4. **Clases CSS de componentes de paginación**: Clases en la etiqueta o contenedor padre (`pagination`, `pager`, `nav-links`, `page-numbers`).
5. **Texto de enlace de paginador**: "Siguiente", "Next", ">", "»", "›" o números enteros de página.

### B. Preservación del Nivel de Profundidad (Depth Invariance)
- **Problema previo**: Si un enlace de paginación se trataba como un hiperenlace ordinario, aumentaba el `depth` (`depth + 1`), agotando prematuramente el `max_depth` (ej. si `max_depth: 3`, solo se podían recorrer 2 páginas).
- **Solución implementada**: Los enlaces reconocidos como paginación de la página actual preservan el mismo nivel jerárquico (`queue.append((p_url, depth))`), permitiendo recorrer la secuencia completa de páginas de un catálogo o listado sin chocar contra el límite de profundidad temático.
