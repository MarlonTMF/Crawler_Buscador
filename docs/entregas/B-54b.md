## 2. Implementación de los 6 guardarraíles de Escalón 5

En `src/crawler/core/recovery_ladder.py` se implementaron los métodos y propiedades requeridos por `docs/arquitectura_integracion.md` §6:

1. **El agente propone, no admite en `inventory.db`**:
   - `_ask_gemini_for_candidates` retorna candidatos de URL.
   - Ninguna función de escalón escribe directamente en SQLite o altera `inventory.db`.
2. **Validación obligatoria por HTTP HEAD**:
   - Se invoca `fetch_and_verify(cand_url)` exigiendo status HTTP 200, Content-Length > 0 y bytes válidos.
3. **Verificación de contenido institucional (D-01)**:
   - Se incorporó `_verify_institution_content(portal, content)` que normaliza y verifica la presencia explícita de palabras clave institucionales legítimas del portal consultado (ej. "banco central de bolivia", "instituto nacional de estadistica", etc.).
4. **Prohibición estricta de cambio automático de dominio (D-01 / B-55)**:
   - `_get_allowed_domains(portal)` extrae dominios autorizados de la configuración yaml y restringe estrictamente cualquier propuesta del agente al dominio del portal. URLs de dominios externos sugeridos por el LLM son descartadas para tratamiento en B-55 (Herencia).
5. **Tope de llamadas por corrida y presupuesto de API (D-08)**:
   - Parámetro `max_gemini_calls: int = 10` y contador `gemini_calls_count`. Al alcanzar el tope, cesan las consultas sin interrumpir el flujo.
6. **Registro del escalón**:
   - Etiquetado formal con `RecoveryRung.RUNG_5_AGENT_GEMINI = 5` (`agente_gemini`).
