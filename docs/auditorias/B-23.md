dice que ya no necesita la bandera. Si la decisión fuera cierta,

## Hallazgos

### 1. El criterio 3 no está demostrado: se sustituyó una fuente real por un mock

El criterio pide que una fuente real que daba 403 pase a extraer documentos.
La evidencia ofrecida es
`test_orchestrator_pipeline_recovers_403_source_via_headless`, que corre
contra `https://waf-source.gob.bo`, un dominio inventado, con `session.get`
parcheado para devolver 403 y un `MagicMock(spec=HeadlessFetcher)` devolviendo
HTML fabricado. Eso prueba el cableado interno — que es valioso y hay que
conservarlo — pero no prueba nada sobre un WAF real.

Peor: **lo que el test verifica no es una descarga.** Siguiendo el camino en
`orchestrator.py:204-250`, el `ResourceItem` se construye a partir del
candidato descubierto más los metadatos de un HEAD; no exige que la descarga
del PDF haya tenido éxito. En el test, el `.get` de ese PDF también devuelve
403. Las aserciones (`len(dataset.resources) == 1`,
`resolved_via_headless is True`) se cumplen igual. Esto es literalmente el
patrón que `CLAUDE.md` marca como la clase de error más cara del proyecto:
"un log que dice 'candidatos descubiertos' no prueba que se descargaron".

**Qué lo cerraría:** poner `use_playwright: false` en `config/source_bcp.yaml`,
correr `python -m src.crawler.main --config config/source_bcp.yaml`, y pegar
la consulta a `inventory.db` mostrando documentos reales con el
`PROCESADO_EXITOSAMENTE` correspondiente — contrastado contra los 25 docs que
B-14 dejó medidos. Si BCP resulta necesitar la bandera igual, eso también es
un resultado válido: se reporta y D-03 se cierra diciendo eso, no lo contrario.
