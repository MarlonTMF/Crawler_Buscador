## Hallazgos

**[1] La primera capa del fix no tiene cobertura de tests — severidad baja, sin acción recomendada**

Los 5 tests ejercitan únicamente `_is_allowed_domain`:

```
$ grep -E "^def test_|_is_allowed_domain" tests/test_discovery.py
  def test_mailto_link_is_not_allowed_domain():      → _is_allowed_domain
  def test_tel_link_is_not_allowed_domain():         → _is_allowed_domain
  def test_javascript_link_is_not_allowed_domain():  → _is_allowed_domain
  def test_real_http_link_on_allowed_domain_still_passes():   → _is_allowed_domain
  def test_relative_url_with_empty_netloc_still_passes():     → _is_allowed_domain
```

El filtro de anclas (`href_lower.startswith(...)`) no lo toca ninguno. Si
alguien borrara esas líneas, los 5 tests seguirían en verde.

**Por qué no pido corregirlo:** la capa sin cobertura es la **redundante**,
no la que sostiene el comportamiento. El argumento de D-06 para tener dos
capas es que un esquema no-HTTP también puede entrar por sitemap o wayback —
y ese camino pasa por `_is_allowed_domain`, que sí está cubierto. El filtro
de anclas es un atajo que evita el `urljoin` en enlaces obviamente
descartables: si desapareciera, el comportamiento seguiría siendo correcto,
apenas marginalmente más lento. Agregar un test que monte un `soup` completo
para cubrir un atajo de rendimiento cuesta más de lo que protege.

Queda anotado para que, si alguien toca ese bloque en el futuro, sepa que los
tests no se lo van a avisar.
