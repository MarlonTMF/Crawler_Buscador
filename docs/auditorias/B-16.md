## 3. Sobre la verificación en entorno limpio

El parte pega `70 passed in 9.14s` desde un worktree en `C:\Temp\wt_b16` con
`PYTHONPATH` explícito, que es lo que pide el protocolo. **No pude reproducir ese
comando exacto**: `git worktree add` no está en el allowlist del auditor y quedó en
"requires approval". Lo que sí pude hacer:

```
$ git status --porcelain
?? docs/auditorias/B-16.md

$ git diff HEAD --stat
(vacío)

$ python -m pytest tests/ -q -m "not live"
......................................................................   [100%]
70 passed in 7.97s
```

El árbol de trabajo es idéntico a HEAD en todo archivo versionado —lo único fuera es
esta acta, que no es código—, así que el paquete editable importa exactamente el
contenido de HEAD y el `70 passed` vale para HEAD. **La cifra del parte se sostiene**,
aunque por un camino distinto al que el protocolo prescribe. El número también sube de
69 a 70, coherente con el test de regresión agregado.

Esto es la segunda vez que el allowlist bloquea una comprobación que el protocolo me
exige (la primera fue `pytest` y `sqlite3`, ya resueltas — ambas corrieron hoy sin
fricción). **Propuesta: agregar `Bash(git worktree add:*)` y
`Bash(git worktree remove:*)`.** Crear y borrar un worktree descartado no modifica el
trabajo auditado, que es lo que la restricción protege.

La regla del proyecto es que una prueba no vale hasta verla fallar, y el parte afirma

## 5. Observaciones (no bloquean el cierre; van a B-24)

**O-1 · ASOFIN trae 3 boletines de ~49 páginas publicadas, y por semillas fijas.**

Es cobertura congelada, no cobertura incremental. B-24 debería decidir si vale entrar al
paginador con `max_pages` mayor o si ASOFIN se marca como fuente que requiere semilla

**O-3 · Quedan 7 recursos HTML en ASOFIN**, de los cuales 4 son notas de prensa sobre

**O-4 · "Audit errors: 0" sigue midiéndose con el fix de `fetch_head` activo.** El

`resource_audit_log`.** En la primera pasada, los dos PDF que el parte mostraba como
prueba existían en el log —de una corrida de 4 minutos antes— y no en el entregable. El
log sobrevive a corridas que el mapa reemplaza; citarlo permite mostrar de buena fe algo
que ya no está. En la corrida final de ASOFIN el log quedó con 25 filas exactas, así que
el desfase se cerró, pero la regla vale igual: el artefacto que se entrega es el mapa.
